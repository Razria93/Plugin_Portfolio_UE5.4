+# Mini Plan: Phase 6-3 Unused Candidate 전체 스캔


+


+## Metadata


+


+- Type: Mini Plan


+- Status: Draft


+- Branch: `feature/ari-unused-candidate-indicator`


+- Related Phase: Phase 6-3. Unused Candidate 표시


+- Related PR: TBD


+- Related Issues: TBD

+  - `Docs/03_Verification/Build_Verification_Log_KR.md`


+


+## Goal


+


+선택 Asset 관계 Tree에 Unused Candidate suffix를 억지로 붙이지 않고, `/Game` 전체 Asset을 대상으로 참조자가 없는 후보 목록을 스캔해 Tree에 표시한다.


+


+Dependencies / Referencers Tree는 선택 Asset의 관계 분석이고, Unused Candidate는 프로젝트 Content 전체에서 참조자가 없는 후보를 찾는 기능이다. 두 기능의 분석 기준이 다르므로 이번 Phase에서는 별도 스캔 버튼과 결과 Tree를 구성한다.


+


+## Scope


+


+포함:


+


+- `Scan Unused Candidates` 버튼 추가


+- `/Game` 아래 Asset 전체 조회


+- Asset Registry `GetReferencers` 결과가 0개인 Asset을 후보로 판정


+- 후보 노드는 `bIsUnusedCandidate`를 true로 저장


+- Tree root를 `Unused Candidates` 그룹 노드로 구성


+- 후보 row를 `DisplayName [ClassName] (Size) [Unused Candidate]` 형식으로 표시


+- Path Filter / Class Filter를 후보 스캔에도 적용


+- Map, Redirector, `/Script`, `/Engine`, Plugin Content, placeholder 제외


+- Soft Reference / Asset Manager / 동적 로딩 제한사항 문서화


+


+제외:


+


+- 선택 Asset 관계 child node에 Unused Candidate 표시


+- Asset 삭제 기능


+- 자동 정리, 이동, quarantine 기능


+- Soft Reference / Asset Manager / 동적 로딩 정밀 분석


+- Cooked build 기준 unused 판정


+- CSV Export 반영


+- 별도 컬럼형 Tree UI


+

+


+## Implementation Steps


+


+1. `FAssetReferenceTreeNode`에 `bIsUnusedCandidate` 메타데이터를 추가한다.


+2. 선택 Asset relation node 생성 흐름에서는 Unused Candidate 판정을 하지 않는다.


+3. `Scan Unused Candidates` 버튼과 callback을 추가한다.


+4. Asset Registry에서 `/Game` 아래 전체 Asset을 조회한다.


+5. Path Filter / Class Filter를 통과한 Project Content Asset만 후보 검사 대상으로 삼는다.


+6. Map, Redirector, 외부 Content, placeholder 성격의 Asset은 후보 검사에서 제외한다.


+7. `GetReferencers(PackageName)` 결과가 0개인 Asset을 후보 node로 추가한다.


+8. 후보 결과가 없으면 `No unused candidates found` placeholder를 표시한다.


+9. 빌드와 에디터 수동 확인 후 문서와 검증 로그를 갱신한다.
