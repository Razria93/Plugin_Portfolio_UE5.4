필터 입력 오류 · 확인과 비교의 범위

  • 개발 당시에는 사용자 제공 이벤트 로그로 Enter 이후 OnCleared 호출과 값 덮어쓰기를 확인했고, 사용자가 수정 후 Escape 복원을 확인했습니다.
  • 추가 QA는 Enter 확정·클릭 확정·Escape 취소·빈 값 확정의 4조건을 확인했습니다.
  • 이전 처리와의 비교는 이전 입력 콜백만 재구성한 Enter 조건에 한정합니다. 과거 전체 빌드는 실행하지 않았고, 이전 처리의 클릭·Escape·빈 값은 비교하지 않았습니다.
  • CSV 10행과 2행은 결과 범위 확인용입니다. 성능 개선 수치나 고유 에셋 수가 아니며, 루트 A는 필터와 관계없이 포함됩니다.
  • 다른 UE 버전에서의 입력 동작은 확인하지 않았습니다.

미사용 후보 탐색 · 후보 판정의 한계

  • 검사 범위는 프로젝트 콘텐츠 /Game 및 하위 폴더입니다. 프로젝트 밖의 모든 콘텐츠를 포함한 탐색을 뜻하지 않습니다.
  • 선택 없이 후보 표시, 폴더·종류 필터와 결과 없음 안내는 개발 당시 실제 화면 근거입니다. 참조받는 에셋의 제외와 원본 이동은 당시 사용자 확인 기록과 구분해 제시합니다.
  • 초기 구현은 작업 중 초안입니다. 출시된 구버전과 현재 버전의 전체 실행 비교가 아니며, 이 사례에 새로운 10월 추가 QA를 수행했다고 주장하지 않습니다.
  • 후보 표시는 삭제 안전 판정이 아닙니다. Soft Reference·Asset Manager·동적 로딩 기반 사용 여부와 대규모 프로젝트 성능은 미검증입니다.

공유·순환 관계 · 개발 당시 화면과 추가 QA

  • 개발 당시에는 순환 방어를 의도적으로 켜고 끈 Blueprint 화면으로 동작을 비교했습니다. 실제 장애를 발견해 방어 코드를 처음 추가한 사례로 해석하지 않습니다.
  • 추가 QA는 별도 Data Asset hard reference 관계입니다. 공유 D를 각 부모 아래 유지하고, 순환 E→F→E는 깊이 2에서 순환으로 표시한 뒤 탐색을 종료했습니다.
  • 개발 당시 Blueprint 및 실제 프로젝트의 재실행, 크래시·성능 실측은 수행하지 않았습니다. 모든 참조 유형의 완전성을 증명하는 검증은 아닙니다.

CSV 저장 · 기본 저장 확인과 모드 전환 QA

  • 개발 당시 사용자 제공 기본 CSV 3개·화면 5장과 수정 코드 빌드 기록이 있습니다. 이 자료를 수정 후 모드 전환 회귀 테스트로 소급하지 않습니다.
  • PR #59의 Codex 자동 리뷰가 결과 트리와 CSV Mode 열의 불일치를 발견했습니다. 수정 코드는 결과 생성 시점의 모드를 별도로 저장합니다.
  • 2026.10.21 추가 QA에서는 방향 버튼만 전환하면 CSV가 유지되고, 재분석하면 새 모드와 결과로 갱신되는 것을 양방향으로 대조했습니다.
  • 과거 전체 빌드 비교와 기존 실제 프로젝트 CSV 전체 재검증은 수행하지 않았습니다.
  • 개발 당시 CSV 저장 검증에서는 Excel 등 외부 스프레드시트 도구로 파일을 여는 검증을 수행하지 않았습니다. 포트폴리오의 CSV 표는 원본 10개 열 중 AssetName·Depth·Mode 3개 열과 전체 3개 데이터 행을 옮긴 표이며 Excel 실행 화면이 아닙니다.
  • CSV 기능 계획에서 저장 경로 선택 대화상자, JSON 출력, 관계 분석 코드의 별도 클래스 전체 분리는 작업 범위에서 제외했습니다. 계획 원문은 Draft 상태의 작업 초안이며 승인 완료 문서로 표현하지 않습니다.

  • 다른 UE 버전, 대규모 프로젝트 성능, 모든 참조 유형의 완전성은 확인하지 않았습니다.
